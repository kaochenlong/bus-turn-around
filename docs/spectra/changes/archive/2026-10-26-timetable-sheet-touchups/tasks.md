## 1. 打的時刻：不用冒號、相同時刻不算改過、游標留著、打錯看得到

- [x] 1.1 Manual edits recomputed in the browser 與 Adding a vehicle 的打字規則，照 design「不裝時間選擇器，改輸入框本身」與「鋪排與微調都在瀏覽器算，打的時刻不用冒號也收」：四個時刻格收規格例子「Typed times」的每一種寫法，`6:00`、`0600`、`600`、`2445` 被接受，`23:70`、`2370`、`60`、`06:0`、`12345` 不收，前後的空白不算。先寫測試看它失敗：把 `app/frontend/timetable/format.test.js` 的 `parseClock` 表改成例子的每一列，另加 ` 0600 `、空字串、`ab:cd`；在 `spec/system/timetable_edit_spec.rb` 加「打 0720：格子顯示 07:20、那一列 06:00、甲站、06:50、30、07:20、08:05、頁首 1 處」與「加一台車打 1500：多一張 4 號車」。再改 `parseClock`，並拿掉四個輸入框的 `pattern` 屬性與 `TimetableSheetComponent::TIME_PATTERN`（`inputmode="numeric"` 與 `placeholder` 留著）。驗證：`yarn test:js` 與 `bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠；`grep -n pattern app/components/timetable_sheet_component.html.erb app/views/timetables/show.html.erb` 沒有結果（內容檢查）。
- [x] 1.2 Manual edits recomputed in the browser 的「相同時刻不算改過」，照 design「鋪排與微調都在瀏覽器算，打的時刻不用冒號也收」：打的時刻等於那一趟現在的發車時，發車格只換成 `HH:MM` 的寫法，不呼叫 `changeDeparture`、不標改過，頁首改過數不變。先在 `spec/system/timetable_edit_spec.rb` 加「原本 07:30 打 0730：格子 07:30、沒有標改過、頁首 0 處」，看它失敗（1.1 之後 `0730` 會被當成改過）。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠。[after: 1.1]
- [x] 1.3 Manual edits recomputed in the browser 的焦點，照 design「改一格發車只更新那張單，不整區重畫」：改發車格只在原本的元素上更新那張單的時刻、停留、退回全天的說明、四小時那一行與頁首數字，不呼叫 `render()`；`row()` 與 `sheet()` 拆成「複製 template」與「填值」，原地更新與整區重畫共用填值那一步；發車格的 keydown Enter 直接送出，之後瀏覽器若再發 `change`，照 1.2 的規則什麼都不做。先寫測試看它失敗：「打 0720 按 Enter：格子 07:20、停留 30、焦點在那一格」、「打 0605 按 Tab：焦點在同一列的返回發車格」、「打 0720 再點同一列的發車格：焦點在那一格、返回那趟是 07:20」，焦點用 `document.activeElement` 的 `data-sheet` 與 `data-index` 比對。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠，原有的改返回那趟、06:45 接不上、刪第一列、加一列、25:70、改過之後換 p 照舊綠；每個例子不超過 5 行。[after: 1.2]
- [x] 1.4 結構會變的修改之後的焦點，照 design「改一格發車只更新那張單，不整區重畫」：Manual edits recomputed in the browser 的加一列整區重畫之後，焦點在那張單（照車號找）的「加一列」輸入框、空的；Adding a vehicle 加完之後，「加一台車」的輸入框是空的，焦點在它上面（用按鈕加的也一樣）。先寫測試看它失敗：「1 號車加一列打 1100 按 Enter：多一列 11:00、焦點在 1 號車的加一列、空的」、「加一台車打 1500 按加一台車：焦點在加一台車的輸入框、空的」。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠。[after: 1.3]
- [x] 1.5 Manual edits recomputed in the browser 的打錯標示（單子上的發車格與加一列），照 design「打錯時紅色描邊與一行說明，只標最近一次被退回的那一格」：讀不出來的時刻照舊標 `data-invalid`（發車格回到原本的時刻、加一列什麼都不加），另外讓那個輸入框帶 `aria-invalid="true"` 與指到說明的 `aria-describedby`，說明出現在那張單表格下面的 `[data-rejection]`，引用打的字（有打字時）並寫出時刻可以怎麼打。退回的狀態只有一份：新的退回先清掉舊的；下一次被接受的時刻（包括相同時刻）、刪列、加列、重新鋪排都會清掉描邊、`aria-invalid`、`data-invalid` 與說明。說明的字放在 `app/components/timetable_sheet_component.yml`（tw 與 en），由單子 template 的 `data-rejected-typed`（含 `%{typed}`）與 `data-accepted-writings` 帶給瀏覽器；紅色描邊（`aria-[invalid=true]:border-red-600`）、紅字（`text-red-700`）、`role="alert"`、說明的 `print:hidden` 是寫死的內容。先寫測試看它失敗：系統測試「打 23:70：格子回到 07:30、`aria-invalid` 是 true、1 號車的說明含 23:70」、「23:70 被退回後打 0605 到同一列的發車格：頁面上沒有 `aria-invalid`、說明不見」、「加一列什麼都沒打就按加一列：說明只寫時刻可以怎麼打」；元件測試在「單子的 template 帶瀏覽器要填的文案」加上 `data-rejected-typed` 含 `%{typed}`、`data-accepted-writings` 有字。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb spec/components/timetable_sheet_component_spec.rb` 全綠，原有的「打 25:70」照舊綠；紅色、`role`、`print:hidden` 做內容檢查，長相在 4.2 截圖給使用者看。[after: 1.4]
- [x] 1.6 Adding a vehicle 的打錯標示，照 design「打錯時紅色描邊與一行說明，只標最近一次被退回的那一格」：「加一台車」的時刻讀不出來時，控制項照舊標 `data-invalid`、什麼都不加、字留在框裡，輸入框帶 `aria-invalid="true"` 與 `aria-describedby`，說明出現在那一塊的 `[data-add-vehicle-rejection]`（`app/views/timetables/show.html.erb`，預設 `hidden`），字讀單子 template 的同一組 data 屬性，不在 view 的 locale 再寫一份；它跟 1.5 共用同一份退回狀態，加一台車成功或其他被接受的修改會清掉它，單子上的退回也會清掉它。先寫測試看它失敗：「加一台車打 25:70：那一塊的說明含 25:70、輸入框 `aria-invalid` 是 true」、「接著打 1500 加一台車：說明不見、多一張 4 號車」。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠，原有的「加車的時刻不合格式」照舊綠。[after: 1.5]
- [x] 1.7 Manual edits recomputed in the browser 的送出時機，照 design「改一格發車只更新那張單，不整區重畫」與「打錯時紅色描邊與一行說明，只標最近一次被退回的那一格」：發車格打過字才送出，送出在按 Enter 或離開那一格（`focusout`）時；元件記住被打過字、還沒送出的那一格（在 `[data-sheets]` 上聽 `input`），不再聽發車格的 `change`。這一條取代 1.3 寫的「之後瀏覽器若再發 `change`，照 1.2 的規則什麼都不做」，並拿掉 1.5 apply 時加的「欄位的字等於頁面寫進去的時刻就不送出」。做完之後，格子被退回、回到原本的時刻，照原樣再打一次那個時刻，按 Enter 或 Tab 都會清掉紅框與說明；沒打字就按 Enter 或離開，什麼都不動。先在 `spec/system/timetable_edit_spec.rb` 寫測試看它失敗：「23:70 被退回後，同一格照原樣打 07:30 按 Tab：頁面上沒有標成錯誤或無效的格子，說明不見」與同一條按 Enter 的版本；另加「1 號車打 23:70 被退回後，在 2 號車的第一個發車格沒打字就按 Enter：1 號車那一格仍標成錯誤，說明還在」，這一條改之前就會過（現在的寫法也不送出），用來確認改完之後沒打字照樣不送出。驗證：`bundle exec rspec spec/system/timetable_edit_spec.rb` 全綠，原有的「返回發車格打 0720 按 Enter，再打 23:70 按 Enter 被退回，按 Tab 離開」、Enter／Tab／點擊之後的焦點、「原本 07:30 打 0730」照舊綠；每個例子不超過 5 行；對 `spec/system/timetable_edit_spec.rb` 跑 `bin/rubocop`；最後 `bin/ci`。[after: 1.6]
