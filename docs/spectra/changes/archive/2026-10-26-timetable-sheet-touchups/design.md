## Context

班表頁 `/routes/:route_id/timetable` 的單子由 `TimetableSheetComponent` 輸出兩個 `<template>`（單子與列），瀏覽器端的 Alpine 元件 `timetable`（`app/frontend/timetable/component.js`）複製它們、填值、掛事件。現況（2026-10-26 讀程式碼）：

- 四個時刻輸入框（每列兩個發車格、每張單的「加一列」、頁底「加一台車」）都是 `type="text" inputmode="numeric"`，帶 `pattern="[0-9]{2}:[0-9]{2}"`。`pattern` 沒有程式讀，格式由 `format.js` 的 `parseClock` 決定：一定要兩碼、冒號、兩碼，時 00 到 29、分 00 到 59。
- 改一個發車格：`departureChanged` 在 `change` 事件裡解析，打錯就在格子加 `data-invalid`、把值改回原本的；打對就 `changeDeparture` 之後 `render()`，用 `replaceChildren` 把所有單子整個換掉，沒有把焦點放回去。`data-invalid` 在 `app/` 裡沒有任何樣式。
- 每列最後一格是刪除鈕（共用的 `BUTTON_CLASSES`，四個字），印出來不印；`fillRows` 把空白列的最後一格當成操作欄藏起來。
- 六個手填欄（職號、姓名、兩個調度員、兩個里程）在螢幕上也顯示，表頭帶 `min-w-20`。

使用者 2026-10-26 的決定與理由寫在 proposal。這份檔只寫怎麼做。

## Goals / Non-Goals

**Goals:**

- 四個時刻格不用打冒號；同樣的時刻打第二次不算改過。
- 改一格之後，游標留在調度員放的地方（Enter、Tab、點擊）；加一列之後游標回到那張單的「加一列」。
- 打錯時看得出來：紅色描邊加一行說明。
- 刪除鈕放在每列最前面，換成圖示。
- 螢幕上不顯示手填欄，印出來照舊。

**Non-Goals:**

- 時間選擇器、↑／↓ 加減分鐘、打錯時保留打錯的字、刪除的復原、刪列之後的焦點：理由在 proposal 的 Non-Goals。
- 頁首、控制項、超時表、資料限制、列印版面、伺服器回應與網址參數。
- 路線頁與換休息試算。

## Decisions

### 不裝時間選擇器，改輸入框本身

班表的時刻是營運日的寫法，時從 00 到 29，加一列加出來的返程、調度員自己打的時刻都可能是 24:45。瀏覽器內建的 `<input type="time">` 只到 23:59；flatpickr 的純時間模式拿 JavaScript 的 Date 做，時也只到 23，手機上預設改用內建的時間輸入，而且 npm 上的最新版 4.6.13 是 2022-04-14 發的。所以現成的選擇器都裝不進來，問題改在輸入框本身解決：不用打冒號、打錯看得到、改完游標留著。

專案加 npm 相依的先例：`buffer-trade-cost-curve` 引用 `route-page-charts` 的理由「不加 npm 相依」，`turnaround-map` 加 Leaflet 時在「資料由伺服器算好寫進回應，前端只畫；route-page-charts 的三個理由各有交代」逐條交代過。打不出 24:45 的選擇器交代不了。

替代方案：自己做點了會跳出來的選擇器（時從 00 到 29 共 30 個、分另一欄）。這是唯一能挑 24:xx 的做法，但要點兩三下加捲動，比打四個數字慢，還要自己處理鍵盤、焦點與在可橫向捲動的表格裡定位，否決。

### 鋪排與微調都在瀏覽器算，打的時刻不用冒號也收

**Supersedes**: timetable-draft / 鋪排與微調都在瀏覽器算，伺服器只給量到的資料

使用者 2026-10-25 拍板：重新鋪排（換 p、休息、每小時發車數）、改時刻、刪列、加列都在瀏覽器算，不送回伺服器。伺服器的回應裡嵌一段 JSON（`script[type="application/json"][data-timetable-data]`），放每個方向每個小時在每個百分位數下的計畫行駛時間與是否退回全天、量到的每小時發車數、兩端的停留分鐘數、兩端的站名、百分位數選項、休息與發車數的範圍。瀏覽器端的 Alpine 元件 `timetable` 讀這段資料，用純函式鋪排（`layout.js`）、算每張單的四小時休息（`rest_windows.js`）、把趟次配成列（`rows.js`）、處理改時刻、刪列、加列（`edits.js`）、格式化時刻與負停留（`format.js`），把單子畫進頁面，重算頁首的車數、每方向班數與手動改過的格數。什麼都不存，換參數會重新鋪排、手動改過的會不見，提醒固定寫在控制項旁邊。改時刻只重算到達、停留、四小時數字與總數，其他趟次的發車不動，接不上的停留印負數；加列照那張單第一趟的方向從打的時刻發，返回那趟從到達加那一端的停留發，兩趟都算改過；刪列刪掉那一列的兩趟。

2026-10-26 改的只有打時刻的規則（使用者同意）：打的時刻可以是一或兩碼的時、冒號、兩碼的分（`5:30`、`05:30`），也可以不打冒號、三或四個數字、最後兩碼是分（`530`、`0530`），前後的空白不算；範圍照舊是時 00 到 29、分 00 到 59。被接受的時刻在發車格裡顯示成兩碼、冒號、兩碼（`05:30`）。打的時刻跟那一趟現在的發車一樣時，只把格子換成這個寫法，不算改過。讀不出來的時刻照舊標成無效、保留原值，另外加上看得到的標示與說明，見「打錯時紅色描邊與一行說明，只標最近一次被退回的那一格」。

理由：這張表的狀態（參數、手動改的格子）只活在分頁裡、不存，算在狀態所在的地方才合理；改一格就看到結果，不用整頁重載。演算法只有 JavaScript 一份，Ruby 不再有鋪排與四小時視窗，所以沒有兩份實作漂移的問題。打時刻的規則放寬，是因為四個輸入框都是 `inputmode="numeric"`：WebKit bug 200226 裡 WebKit 工程師說 iOS 13 起它叫出只有 0 到 9 的數字鍵盤，一定要冒號的話 iPhone 上可能打不出合格的時刻（沒有拿實機測過）；桌機上也少按一鍵。相同時刻不算改過，是因為放寬之後 `0730` 和格子裡的 `07:30` 字串不同、會被送出；以前一定要打成 `07:30`，打一樣的字瀏覽器根本不發 `change`，也就不會被算成改過。發車格改成打過字就送出之後（見「改一格發車只更新那張單，不整區重畫」），照原樣再打一次 `07:30` 也會送出，同樣不算改過。

替代方案：伺服器重算（2026-10-25 被取代的那一條）；伺服器算第一版、瀏覽器只算微調（同一套演算法兩份，否決）。打時刻的部分：拿掉 `inputmode` 讓手機跳完整鍵盤（不用改規格，但手機要多切一次鍵盤、桌機沒有變好用，否決）；打字時當場補上冒號（只收四碼，刪字、貼上、改中間的字都要另外處理；使用者 2026-10-26 選了送出時補上，否決）。

### 改一格發車只更新那張單，不整區重畫

改發車格不會改變單子的結構：`changeDeparture` 只換掉同一個位置的那一趟，車數、每張單的趟數、列數都不變。所以這種修改不再呼叫 `render()` 整區重畫，改成在原本的元素上填新值：那張單每一列的時刻與停留、退回全天的說明、四小時那一行，加上頁首的數字。輸入框本身沒有被換掉，焦點就照瀏覽器原本的規則走：Enter 留在原格，Tab 跳到下一個控制項，打完直接點別的格子或按鈕，點擊也不會丟。

為了不讓「整區重畫」與「原地更新」各寫一份填值的程式，現在的 `row()` 與 `sheet()` 拆成「複製 template」加「填值」兩步，原地更新只呼叫填值那一步，兩條路填的是同一份程式。

發車格什麼時候送出由頁面自己決定，不靠瀏覽器的 `change`：元件記住被打過字、還沒送出的那一個發車格（只有聚焦的那一格打得進字，所以最多一格），在那一格按 Enter（keydown，跟「加一列」的寫法一樣）或離開它（`focusout`）時才送出，送出時先忘掉它。沒打字就按 Enter 或離開，什麼都不做；照原樣再打一次格子裡的時刻也算打過字，走相同時刻那條路：只換寫法，並清掉退回的標示。發車格的 `change` 不再聽。

這一段原本寫的是「發車格的 keydown Enter 直接送出；之後瀏覽器如果又發 `change`，讀到的就是剛剛填進去的時刻，照上一條的規則什麼都不做」。2026-10-26 apply 時在 headless Chrome（selenium）試過，這個寫法不成立，使用者同一天選了現在的寫法（task 1.7）：

- 同一格先打 `0720` 按 Enter 被接受，再打 `23:70` 按 Enter 被退回，接著按 Tab 離開，Chrome 還會發一次 `change`，讀到的是頁面放回去的 07:20。相同時刻那條路會清掉退回的標示，所以紅框一離開就不見。看起來 Chrome 是拿這一格第一次打字之前的值來比，頁面自己改寫的值不算數。
- apply 1.5 時加了一條擋掉它：欄位的字等於頁面寫進去的時刻，就不送出。這條也把照原樣重打當成沒打字：在 `bin/dev` 上，格子被退回、回到 05:00 之後再打一次 `05:00`，按 Enter 或 Tab 紅框都還在，打 `0500` 才清掉，跟「打錯時紅色描邊與一行說明，只標最近一次被退回的那一格」寫的「包括跟原本一樣的時刻」不符。
- 照原樣重打再按 Tab，Chrome 根本不發 `change`。所以只要還靠 `change`，這種情況的紅框就清不掉。

會改變結構的修改（刪列、加列、加一台車、重新鋪排）照舊整區重畫。加一列之後，焦點放回那張單（照車號找）的「加一列」輸入框，它在重畫之後是空的。加一台車的輸入框不在單子那一區裡，重畫不會換掉它，加完清空、把焦點放在它上面。

替代方案：照舊整區重畫，重畫完再把焦點放回同一個位置的元素。按 Tab 時焦點已經移到下一格，要先記住它；在 mousedown 與 mouseup 之間重畫的話，點擊的目標已經被換掉，點擊會丟掉，否決。送出的時機：欄位的字等於頁面寫進去的時刻就不送出（apply 1.5 時的寫法，不用多一份狀態，但照原樣重打清不掉紅框，否決）；記住有沒有打過字、離開時照樣靠 `change`（照原樣重打再按 Tab，Chrome 不發 `change`，按 Enter 清得掉、按 Tab 清不掉，否決）。

### 打錯時紅色描邊與一行說明，只標最近一次被退回的那一格

讀不出來的時刻照舊：發車格標 `data-invalid`、值改回原本的時刻；「加一列」「加一台車」的控制項標 `data-invalid`、什麼都不加、字留在框裡。另外加上：

- 那個輸入框帶 `aria-invalid="true"`，描邊換成紅色（`aria-[invalid=true]:border-red-600`，Tailwind 4.3.3 內建的 aria 變體沒有 invalid，所以用方括號的寫法）。
- 說明：發車格與「加一列」的說明在那張單的表格下面（`[data-rejection]`），「加一台車」的說明在那一塊裡（`[data-add-vehicle-rejection]`）。字是紅色（`text-red-700`），帶 `role="alert"`，輸入框用 `aria-describedby` 指到它。內容是「「打的字」不是時刻。」加上時刻可以怎麼打；沒有打字時只寫時刻可以怎麼打。說明不印。
- 一頁同時最多標一格：新的退回會先清掉舊的；下一次被接受的時刻（包括跟原本一樣的時刻，照原樣再打一次也算；沒打字就按 Enter 或離開不算）、刪列、加列、加一台車、重新鋪排，都會清掉描邊、`aria-invalid` 與說明。發車格的 `data-invalid` 也一起清掉。
- 離開這一頁再按上一頁回來，頁面上沒有紅框與說明。Turbo 會把離開時的頁面存進快取，按上一頁時拿出來用；回來的元件是新的，不知道快取裡的標示。單子會整區重畫，上面的標示跟著不見，但「加一台車」那一塊不在單子裡，標示會一直留著，之後再也清不掉。所以元件在 `turbo:before-cache`（Turbo 存快取之前）先清掉退回的標示，元件拆掉時（`destroy()`）拿掉這個監聽；`application.js` 的首頁插圖（`homeHero`）與地圖（`lazyMap`）也是在這個事件把狀態放回去。這一條是 2026-10-26 apply 1.6 時發現的：先寫的系統測試在改之前失敗，「加一台車」的說明在上一頁回來之後還在。

紅色是網站第一次用，使用者 2026-10-26 指定打錯時用紅色描邊；只用在被退回的輸入框與它的說明，網站其他地方不加。`border-red-600` 對白底的對比約 4.8:1，`text-red-700` 約 6.4:1（把 Tailwind 4 的 OKLCH 色值換成 sRGB 算的，沒有在瀏覽器量）。

說明的字放在 `timetable_sheet_component.yml`，由單子的 template 用 data 屬性帶給瀏覽器（`data-rejected-typed` 留 `%{typed}` 的位子，`data-accepted-writings` 寫時刻可以怎麼打）。這延續 `timetable-draft` 的「單子的標記由伺服器的 template 給，瀏覽器只填值」；「加一台車」的說明也讀同一組字，不在 view 的 locale 裡再寫一份。

替代方案：說明放在發車格裡面、輸入框下方（`.data-table` 的格子不換行，說明會把那一欄撐寬，整張表跳動，否決）；只靠 `title`（觸控螢幕看不到，否決）；用琥珀色（這一頁「需要 JavaScript」那一句已經用 `border-amber-300 bg-amber-50`，但使用者要紅色，否決）。

### 刪除鈕是每列最前面的垃圾桶圖示

列的 template 與表頭的操作欄（表頭那一格只有 sr-only 的「操作」）從最後一格移到第一格，印出來照舊不印。`fillRows` 補的空白列，藏起來的是第一格。

按鈕只有圖示：描邊的垃圾桶（蓋子一條橫線、把手、桶身、桶身裡兩條直線），照網站既有的內嵌 SVG 畫法（`aria-hidden="true"`、`viewBox="0 0 24 24"`、圓頭圓角、`fill-none stroke-2`，例如 `load_profile_table_component.html.erb` 的展開箭頭），用 `stroke-current` 跟著按鈕的字色變，`size-5`。按鈕另給一組 class（`ICON_BUTTON_CLASSES`）：36px 正方形（`size-9`，跟 `BUTTON_CLASSES` 的 `min-h-9` 一樣的點擊範圍）、沒有描邊、`text-slate-500`，滑過去 `bg-slate-100 text-slate-900`，鍵盤焦點的 outline 照抄 `BUTTON_CLASSES`。`BUTTON_CLASSES` 是「加一列」也在用的文字按鈕，不動它。

「刪這一列」放在 `title`（滑過去會跳出來，跟改過的發車格的「手動改過」同一種做法）與 `aria-label`。Capybara 3.40.0 的 button 定位會比對 `title`（`aria-label` 要開 `enable_aria_label` 才比對，這個專案沒開），所以 `spec/system/timetable_edit_spec.rb` 的 `click_button "刪這一列"` 不用改。

替代方案：保留跟「加一列」一樣的描邊（一致，但每列一個，十幾列會變成一整排方塊，比時刻格還搶眼，使用者 2026-10-26 照建議選了沒有描邊）；滑過去變紅色（紅色只給打錯用，否決）。

### 單子一車一張、一列一個來回；印出來的欄位照行車憑單，螢幕上不顯示手填欄

**Supersedes**: timetable-draft / 單子一車一張、一列一個來回，欄位照行車憑單

每台車一張單，一列是一個來回：去的那趟與接著回的那趟。欄位照紙本行車憑單的順序：職號、姓名、發車時間、起點、調度員、預計到達終點（到達時刻）、停留（返回那趟發車減到達，分鐘）、預計返回起點（返回那趟的發車時刻）、累計里程、預計返站時間（返回那趟的到達時刻）、回站後停留（下一列發車減這一列返站，分鐘，最後一列空白）、行駛里程、調度員。停留與回站後停留是我們加的，緊跟在對應的時刻後面；職號、姓名、兩個調度員、兩個里程印出來是空白，給人手填；列不編號。最後只剩單程時，返回那三欄空白。單子的標題是「車次 N」：紙本左上角的「車次」是這一張單、這台車當天這一班的編號，一張單一個，不是每一列的編號（2026-10-25 對照照片改過來，第一版誤當成列號）。單子上不出現任何車牌：班表根本不讀 `bus_id`，印出來的「車號」是空格給人手填。

「車次」在詞彙表是趟次的「不要用」說法，這裡保留它當單子的編號，因為它要跟紙本行車憑單對得起來；寫進 `docs/spectra/LANGUAGE.md`「班本」那條的邊界。

2026-10-26 改的只有螢幕（使用者同意）：螢幕上不顯示六個手填欄，表頭與格子都是 `hidden print:table-cell`，拿掉表頭的 `min-w-20`；螢幕上每列最前面是刪除鈕（見「刪除鈕是每列最前面的垃圾桶圖示」）。印出來照紙本 13 欄，欄寬照舊由表頭的 `data-column` 決定。格子還在 HTML 裡，只是螢幕上不顯示，所以列的 template 的欄序照舊是紙本的順序，前面多一格操作欄。

理由：使用者提供的行車憑單照片就是這個格式，調度員拿到不用學。拿到手的是印出來那張，所以這個理由照樣成立；螢幕是改班表的地方，手填欄在螢幕上永遠是空的、不能打字，卻佔約 600px（估的：每欄至少 80px 加上 24px 內距），表格能用的寬度約 1024px（照 class 算的：`page-column` 的 `max-w-6xl` 扣掉頁面與單子的內距），整張表約 1500px（估的）。拿掉之後估起來剩約 850px，桌機上應該不用再橫向捲動；手機照樣要捲。這兩個數字在驗收時量了，實測值寫在 Risks。

替代方案：欄留著、只拿掉 `min-w-20`，讓欄縮到表頭字的寬度（只省約 230px，估的，表還是比畫面寬，否決）；加一個「顯示手填欄」的開關（多一個控制項，列印預覽本來就看得到，否決）。

### 測試：分支與焦點寫斷言，顏色與圖示截圖給使用者看

照 `.spectra.yaml` 的 `tdd: true`，每一組先寫會失敗的測試再改程式。照 `small-sample-grey` 的決定「測試沿用既有的分支例子，class 與文字在瀏覽器驗」，寫死的 class 與圖示不寫斷言：紅色描邊、紅字、垃圾桶的長相、沒有描邊的按鈕，在瀏覽器截圖給使用者看，由使用者判斷。寫斷言的是有分支或會變的東西：

- `parseClock` 的每一種寫法（Vitest，照規格的例子「Typed times」）。
- 打對、打錯、相同時刻三條路，以及 Enter、Tab、點擊、加一列之後焦點在哪（系統測試，`:js`）。焦點用 `document.activeElement` 讀它的 data 屬性比對。
- 退回時 `data-invalid`、`aria-invalid` 與說明出現，下一次被接受的修改清掉它們（系統測試）。
- 什麼時候送出：被退回之後照原樣重打，按 Enter 或 Tab 都清掉標示；沒打字就在別格按 Enter 不清；Enter 被接受、再被退回、接著按 Tab 離開也不清（系統測試）。離開這一頁再按上一頁回來，沒有標示（系統測試：從網站名稱列的首頁連結離開，再用瀏覽器的上一頁回來）。
- 手填欄：列印樣式下是 `table-cell`、螢幕上看不到（`spec/system/timetable_print_spec.rb` 本來就用 computed display 驗這一類）；列的 template 欄序（元件測試）。

每個例子照專案的 `RSpec/ExampleLength` 不超過 5 行。

## Implementation Contract

**看得到的行為**

- 四個時刻格收規格「Typed times」的每一種寫法；發車格送出之後顯示 `HH:MM`（營運日的寫法，24:45 照樣寫 24:45）；「加一列」「加一台車」送出之後清空。
- 打的時刻等於那一趟現在的發車（照原樣再打一次格子裡的時刻也算）：格子換成 `HH:MM`，不標改過，頁首改過數不變；除了清掉退回的標示，其他什麼都不動。
- 發車格打過字才送出，送出在按 Enter 或離開那一格時；沒打字就按 Enter 或離開，什麼都不動，退回的標示也留著。
- 改發車格：同一張單的到達、停留、四小時那一行與頁首數字更新，元素不換；Enter 之後焦點在原格，Tab 之後在下一個控制項，點了別的格子焦點就在那一格。
- 加一列：整區重畫，焦點在那張單的「加一列」輸入框、空的。加一台車：焦點在「加一台車」的輸入框、空的。
- 讀不出來的時刻：發車格回到原本的時刻並標 `data-invalid`；「加一列」「加一台車」的控制項標 `data-invalid`、字留著。被退回的輸入框 `aria-invalid="true"`、紅色描邊；說明出現在那張單的表格下面或「加一台車」那一塊裡，引用打的字（有打字時），寫出時刻可以怎麼打。一頁最多一處；下一次被接受的時刻、刪列、加列、加一台車、重新鋪排都會清掉它；離開這一頁再按上一頁回來，頁面上沒有它。
- 每列第一格是刪除鈕：垃圾桶圖示、沒有描邊、`title` 與 `aria-label` 是「刪這一列」；印出來不印。
- 螢幕上看不到職號、姓名、兩個調度員、兩個里程；印出來照紙本 13 欄，空白。

**介面**

- `parseClock(text)`（`app/frontend/timetable/format.js`）：回傳營運日的分鐘數或 `null`。先去掉前後的空白，再收兩種寫法：`^\d{1,2}:\d{2}$`，或 `^\d{3,4}$`（最後兩碼是分、前面是時）；時大於 29 或分大於 59 回 `null`。`fieldClock`、`clock` 不變。
- `TimetableSheetComponent::TIME_PATTERN` 與四個輸入框的 `pattern` 屬性拿掉；`inputmode="numeric"` 與 `placeholder="HH:MM"` 留著。
- `TimetableSheetComponent`：新增 `ICON_BUTTON_CLASSES`；表頭與列的 template 第一格是操作欄；手填欄的表頭與格子帶 `hidden print:table-cell`、表頭不再帶 `min-w-20`；單子的 template 在表格下面多一個預設 `hidden`、`print:hidden` 的 `[data-rejection]`（瀏覽器複製單子時照車號給它 `rejection-<車號>` 的 id，`aria-describedby` 指到它；「加一台車」的說明用固定的 id），並帶 `data-rejected-typed`（含 `%{typed}`）與 `data-accepted-writings`。元件同層的 `.yml` 加這兩句的 tw 與 en。
- `app/views/timetables/show.html.erb`：「加一台車」那一塊多一個預設 `hidden` 的 `[data-add-vehicle-rejection]`；輸入框拿掉 `pattern`。
- `component.js`：元件記住被打過字、還沒送出的發車格（在 `[data-sheets]` 上聽 `input`，最多一格）；發車格的 keydown Enter 與 `focusout` 交給同一個送出函式，那一格是被打過字的才送出，送出時先忘掉它；不再聽發車格的 `change`，apply 1.5 時加的「欄位的字等於頁面寫進去的時刻就不送出」拿掉。送出分三條路（讀不出來、跟現在一樣、改了）；「改了」那條原地更新那張單與頁首，不呼叫 `render()`；退回的狀態只有一份（哪個輸入框、哪個控制項、哪個說明），由一個函式設、一個函式清；`render()` 清掉它；`init()` 在 `document` 上聽 `turbo:before-cache` 清掉它，`destroy()` 拿掉這個監聽；`fillRows` 藏第一格。

## Risks / Trade-offs

- [iPhone 打不出冒號是讀 WebKit bug 推的，沒有實機測] → 不打冒號也收之後，鍵盤有沒有冒號都打得進去；上線後請使用者在 iPhone 上試一次。
- [表格寬度的數字原本是估的] → 2026-10-26 驗收時在 `bin/dev` 用 headless Chrome（CDP 模擬寬度）量了 2026-10-22 的中山幹線（23 張單）、251（10 張）、307（82 張），每條路線取所有單子的最小到最大值。1280px 寬：改之前表格那一層的 `clientWidth` 是 1022px，`scrollWidth` 是 1308 到 1438px（估的是 1024px 與 1500px）；改之後 `scrollWidth` 等於 `clientWidth`，都是 1022px，表格內容本身 782 到 912px（表格是 `width: 100%`，暫時把寬度設成 `max-content` 量的；估的是 850px），桌機上不用再橫向捲動。390px 寬：框是 316px，改之前內容 1178 到 1301px，改之後 652 到 775px，手機照樣要捲。
- [瀏覽器的 `change` 跟「調度員有沒有打字」對不上：Enter 時發不發，各家不一致；2026-10-26 在 headless Chrome 試過，頁面改寫過欄位之後離開，Chrome 還可能發 `change`，照原樣重打再離開則不發] → 發車格不聽 `change`，由元件記住打過字的那一格，在 Enter 與 `focusout` 時送出；系統測試鎖住上面這幾種情況。只在 Chrome 試過，Safari 與 Firefox 沒有試。
- [`focusout` 每次離開那一格都會發，`change` 只在字跟之前不同時發；切到別的視窗時兩者發不發都沒有試] → 只有打過字才送出。如果切走時 `focusout` 會發，打到一半切走，那一格就會先被送出，讀不出來就被退回；上線後請使用者留意。
- [原地更新與整區重畫填值的方式漂移] → 兩條路共用同一組填值函式；系統測試同時涵蓋改發車（原地）與加列、刪列（重畫）。
- [`role="alert"` 在 `hidden` 切換時各家螢幕報讀唸不唸不一定] → `aria-invalid` 與 `aria-describedby` 把說明接在輸入框上，聚焦時會唸；沒有拿螢幕報讀軟體測。
- [螢幕與紙本長得不一樣] → 印出來的版面完全不變；列印預覽看得到手填欄。
- [紅色第一次進網站] → 只用在被退回的輸入框與說明，寫在這一條；之後要用在別處另外決定。
