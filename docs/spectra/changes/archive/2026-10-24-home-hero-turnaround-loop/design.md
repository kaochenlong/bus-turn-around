## Context

首頁插圖的動畫現在的樣子：

- `app/frontend/hero/scene.js`：`buildScene()` 回傳場景與 `parts`（公車、前門兩片門板、司機），`pose(parts, t)` 依 t（0 到 1）擺姿勢，總長 `DURATION = 5.5` 秒，`TIMELINE` 分五段：drive 0–3.0、door 3.0–3.8、stepOut 3.8–4.6、walk 4.6–5.2、lean 5.2–5.4。`pose(parts, 1)` 是匯出靜態圖的姿勢。公車的材質用一個切面（`BLOCK_EDGE`，x = −15）切在地塊左緣，陰影一起切；站牌旁的三個民眾（`riders()`）與調度站裡的站長不動，也沒有切。
- `scene.js` 的 `person()`：方塊拼的人，總高約 1.82。兩根 0.84 高的直角腿（slate-800）、0.52×0.62×0.3 的身體（圓角 0.06）、0.13×0.58×0.17 的手臂、0.3×0.32×0.3 的灰色頭（slate-300）、頭頂與腦後各一片頭髮，沒有五官。頭約佔身高的 1/5.7。
- `app/frontend/hero/runtime.js`：`start(section)` 插入 canvas，每格 `pose` 再 render，t 到 1 就停止 `requestAnimationFrame`，把 `data-hero` 設成 `done`。停下之後由 `ResizeObserver` 在尺寸改變時重畫一格；跨過 640 px 換鏡頭，寫在 `data-hero-shot`。回傳 `{ dispose }`。
- `app/frontend/entrypoints/application.js`：Alpine 元件 `homeHero` 判斷減少動態效果與 WebGL，按需 import runtime，`turbo:before-cache` 把 `data-hero` 還原成 `pending`，`destroy()` 釋放 renderer。
- `app/frontend/stylesheets/application.css`：`loading`、`playing`、`done` 時藏起靜態圖、保留盒子；`pending` 在 `@media (scripting: enabled) and (prefers-reduced-motion: no-preference)` 下先藏、3 秒後自己顯示。這幾條在 Tailwind 的 `@layer` 外面，蓋得過 utilities。
- `HomeHeroComponent` 輸出 `section[data-section=hero][x-data=homeHero][data-hero=pending]`，裡面的 `[data-hero-stage]` 只有 `<picture>`。
- `tools/hero/index.html`：匯出頁，`?shot=` 選鏡頭、`?t=` 用 0 到 1 的比例擺姿勢，匯出一律 `pose(parts, 1)`。
- 測試：`spec/components/home_hero_component_spec.rb` 有三個例子（picture 的兩個來源、`pending` 與 `x-data`、img 的寬高與 alt）。`spec/system/home_hero_spec.rb` 有九個例子，其中三個靠 `data-hero=done` 判斷：「播一次就停止重繪」、「首頁 → 路線頁 → 上一頁」的重播、「播完之後畫面變窄」。系統測試的視窗是 1400×1400（`spec/support/system.rb`）。`spec/assets/home_hero_images_spec.rb` 檢查兩張 WebP 存在，全景不超過 200,000 bytes、直式不超過 120,000 bytes；現在的檔案是 39,576 與 25,318 bytes（`ls -l`，2026-10-23）。

先前的決定，都在 `home-page`：

- 「插圖在首頁執行期播一次動畫，靜態圖當備援」：每次進首頁播一次、不循環；循環播放當時列為不在範圍內，沒有寫反對的理由。
- 「執行期效能預算：pixel ratio 上限 2、陰影貼圖 2048、只在播放時重繪」：理由是怕執行期在司機的手機上付不起。量到的數字（2026-10-23）：動畫 chunk brotli 後 110,374 bytes（預算 200 KB）；每格中位數桌機 2.4 ms、模擬手機 1.8 ms（預算 16 ms，開發機 headless Chrome 開 4 倍 CPU 節流）；實機的 GPU 時間沒量。
- 「構圖與風格：一張圖講司機的休息，色票鎖在路線頁，不畫五官，通用公車」：收斂的色票與不畫五官，是把插圖壓回「插畫」、不讓公運處、審議會、記者讀成「玩具」最省事的兩招。原本照舊；需求變更之後，人物與色票的部分由這個 change 改掉，見「人物改成圓頭、點點眼睛與膚色」與「路邊種三棵行道樹與兩個花台，調色盤多一個綠色」。
- 「先保留插圖的空位再播，3 秒內沒有接手就顯示靜態圖」、「場景模組放 app/frontend/hero，首頁與匯出頁共用，three 改為 dependency」：這次都照舊。
- 「插圖動畫用 Alpine 元件按需載入，Turbo 快取前還原成伺服器輸出」：照舊，只換兩個細節：播完設成 `done` 的那一步拿掉（見「data-hero 拿掉 done，加上 paused」），`data-hero-shot` 的 `tall` 改名成 `narrow`（見「手機畫面改成 3:2，鏡頭跟著公車移到站牌」）。
- 「匯出直接從 canvas 出 WebP，兩個鏡頭、固定尺寸」：原本照舊；第三次需求變更改了全景的尺寸，見「全景改成約 2.1:1，鏡頭只框地塊與從左緣開進來的車頂」。

使用者的要求（2026-10-23）：動畫不要停在司機下車，要繼續演、有車來來去去。討論後選了在同一塊場景裡一直循環，不放大成停車場。apply 做到 13/15、使用者看畫面時，又覺得方塊人「不太可愛」，看過三種人的比較圖後選了圓頭加點點眼睛與膚色。apply 做到 18/20 時，使用者再要路邊種樹、調度室牆上貼一張海報：綠化看過比較圖後選了用綠色的行道樹加花台，海報看過示意圖後選了照片上那張「洋流」海報的樣子。apply 做到 24/26 時，使用者看桌機的畫面，覺得插圖上下留白太多。apply 做到 29/31 時，使用者發現手機上看不到重點動畫，看過比較圖後選了鏡頭跟著故事橫移，並要手機畫面的上下留白也收緊。

先前在其他 change 的紀錄，跟海報有關的一條：`home-origin-story` 的非目標「報導之後的發展：論文進度、公運處的四大藥方與 2026-09-21 的回應、沈伯洋的政見與 2026-09-22 的會面……」，理由寫明候選人的名字在 2026-11-28 選舉前出現在首頁，網站會被讀成某一邊的，而公運處與選後的新市府都是這個網站要說服的對象。照沈伯洋競選官網 HEART 政策島的頁面，它的吉祥物就叫「洋流」；20261128 是投票日（`docs/background.md`）。

## Goals / Non-Goals

**Goals:**

- 動畫演出一次完整的折返：車停下、司機休息、休息結束、車開到站牌載客、開走、下一台進來，一圈接一圈。
- 定格畫面的姿勢跟現在的最後一格相同；人物、綠化與海報加進來之後，靜態圖重新匯出，沒有 JS 與減少動態效果的人看到的也是新的畫面。
- 人物看起來親切一點：圓頭、點點眼睛、膚色，但不做成 HEART 政策島那種大頭、腮紅、多種髮型的畫法。
- 路邊有幾棵樹與花台，但不擋到司機、車門、站牌與民眾；調度室後牆貼著使用者要的那張海報。
- 桌機與手機上的插圖都不留多餘的上下空白；手機上也看得到上車、開走與民眾走回來。
- 看的人能把動畫停下來；沒人看得到的時候（插圖捲出畫面、分頁在背景）不畫。
- 每格耗時與 chunk 大小仍在原本的預算內，做完重新量。

**Non-Goals:**

- 停車場、多台車同時進出；照沈伯洋競選官網「HEART 政策島」的人物畫法（大頭、腮紅、多種髮型）、樣子的其他部分或互動做（理由見 proposal）。
- 人物的腮紅、髮型變化、每個人不同的膚色、手掌與鞋子。
- 路對面的一排樹、更多的樹或花草、街道家具；海報上的日期等細節與其他海報。
- 插圖的互動（拖曳旋轉、縮放、滑鼠視差）與其他頁面的 3D。
- 動畫裡的時鐘、倒數或任何數字。
- 乘客在末站下車、人物走路的腿部動作、站長的動作。
- 跨頁或跨次造訪記住暫停。
- 限制每秒畫幾格。
- 動畫播放時螢幕閱讀器讀不到插圖的 alt（現在就有的行為，另開 change）。

## Decisions

### 插圖循環演一圈折返，定格畫面是司機靠在車旁那一格

**Supersedes**: home-page / 插圖在首頁執行期播一次動畫，靜態圖當備援

首頁的動畫改成一圈一圈的折返，插圖看得到、沒有暫停的時候一直循環。每次進首頁都從第 0 秒（公車開進來）開始。一圈的時間軸是設計值，apply 時可微調；前 5.5 秒照舊：

| 秒數 | 發生什麼 | 跟現在的關係 |
| --- | --- | --- |
| 0–3.0 | 公車從地塊左緣外開進來，減速停在末站 | 現在的 drive |
| 3.0–3.8 | 前門打開 | 現在的 door |
| 3.8–4.6 | 司機從門口走出來 | 現在的 stepOut |
| 4.6–5.2 | 走到前輪與車門之間 | 現在的 walk |
| 5.2–5.4 | 往後靠 | 現在的 lean |
| 5.5 | 定格畫面（`STILL`） | 現在的最後一格 |
| 6.3–7.9 | 伸懶腰：兩手舉過頭再放下，一次 | 新的 |
| 8.4–8.8 | 站直，轉身面向車頭 | 新的 |
| 8.8–11.2 | 沿車身走回門口、轉向車門、走進車裡，看不見 | walk 與 stepOut 反過來 |
| 11.2–11.0 | 前門關上 | door 反過來 |
| 11.0–12.6 | 公車往前開，前門停在站牌右邊一點 | 新的 |
| 12.6–13.4 | 前門打開 | 新的 |
| 13.4–16.1 | 三個民眾從最靠近的開始依序走到門口、進到車裡，繞過站牌桿、不互相穿過 | 新的 |
| 16.2–17.0 | 前門關上 | 新的 |
| 17.0–19.4 | 公車加速，從地塊右緣開出去 | 新的 |
| 18.4–20.8 | 三個民眾從右緣外走進來，停在原本等車的位置、轉回原本的朝向 | 新的 |
| 21.0 | 一圈結束（`CYCLE`），下一圈從 0 開始 | 新的 |

apply 時調過的地方（2026-10-23）：前門如果停在站牌正後方，從鏡頭的角度看會被站牌板擋住，民眾走到門口就看不見了，所以公車多開一點，讓門口在站牌右邊（`scene.js` 的 `KERBSIDE`）。三個民眾改成最靠近的先上車，最後一位 16.06 秒進到車裡，關門與開走跟著往後挪 0.2 秒。民眾上車與走回來的時刻由 `RIDERS` 的出發時間、路線和步行速度算出來，不是手填的。

定格畫面是一圈裡的第 5.5 秒：公車停在末站、前門開著、司機靠在車旁、三個民眾在站牌前、路上沒有別的車。它跟原本的 `pose(parts, 1)` 是同一個姿勢；2.1 到 2.4 用原本的方塊人逐像素比對過，確認姿勢沒有變。人物後來換成「人物改成圓頭、點點眼睛與膚色」的造型，之後又加了「路邊種三棵行道樹與兩個花台，調色盤多一個綠色」與「調度室後牆貼一張洋流海報，貼圖照使用者給的樣子」，兩張 WebP 因此重新匯出（7.3、8.4）；第三次需求變更又改了全景的尺寸與鏡頭，再匯出一次（9.3）；第四次需求變更改了手機的畫面，又匯出一次（10.2）。「先保留插圖的空位再播」照舊，沒有 JS、減少動態效果、沒有 WebGL、chunk 載入失敗、元件啟動前出錯的退路也照舊。動畫裡不放時鐘、倒數或任何數字，車停多久只是示意。

休息要看得出是休息：現在司機下車後只往後靠了約 7 度（`RESTING.lean = -0.12`），使用者看到的是「下車就沒了」。伸懶腰是兩隻手臂一起舉過頭，在全景圖上人物大約 50 px 高時也讀得出來（估計，11.1 看畫面確認）。

理由：網站量的折返停留是「本趟末站到站到下一趟起站離站之間的時間」（`docs/spectra/LANGUAGE.md`）。現在的動畫只演到這段的開頭就定格，定格在司機休息，看起來像他可以一直休下去；演到車開去站牌、載客、開走，畫面才跟標題的問題一致。場景本來就留了這段：`scene.js` 對那三個民眾的註解，寫的就是在等這台車下一趟。一圈接一圈，也對得上起點區塊那張時刻卡（06:50 發車、09:50 回站、10:00 又發車）。使用者在討論時選了一直循環（2026-10-23）。

替代方案：

- 演完一圈就停（否決：最後還是停在司機休息的畫面，使用者現在的問題大約半分鐘後會再出現一次）。
- 放大成停車場、多台車同時進出（否決：理由見 proposal 的非目標）。
- 動畫從定格畫面開始演（否決：`home-page` 已經否決過「先顯示靜態圖再從頭播」，使用者要看到公車開進來）。

### 首頁插圖的非目標拿掉循環播放，互動與其他頁面的 3D 照舊不做

**Supersedes**: home-page / 插圖的互動（拖曳旋轉、縮放、滑鼠視差）與循環播放：動畫每次進首頁播一次就停。其他頁面放 3D 也不在範圍內。

`home-page` proposal 的這條非目標裡，循環播放與「動畫每次進首頁播一次就停」改由「插圖循環演一圈折返，定格畫面是司機靠在車旁那一格」決定。插圖的互動（拖曳旋轉、縮放、滑鼠視差）與其他頁面放 3D 照舊不做，寫在這個 change 的非目標裡。

理由：使用者這次只要求動畫繼續演、車來來去去，沒有要求互動。

替代方案：整條非目標一起拿掉（否決：沒有人要求互動；拖曳旋轉正是 HEART 政策島的互動方式，不借它的理由見 proposal 的非目標）。

### home-page design 列的同一條非目標也只拿掉循環播放

**Supersedes**: home-page / 插圖的互動（拖曳旋轉、縮放、滑鼠視差）、循環播放，以及其他頁面的 3D。

`home-page` design 的 Goals / Non-Goals 用另一種寫法列了同一件事，處理方式跟「首頁插圖的非目標拿掉循環播放，互動與其他頁面的 3D 照舊不做」相同：循環播放改由這個 change 決定，插圖的互動與其他頁面的 3D 照舊是非目標。

理由：一條決定只能取代一筆紀錄，兩種寫法要各自標明，`spectra decisions` 才不會把舊的那筆當成還有效。

替代方案：只取代 proposal 那一筆（否決：design 那一筆會繼續被列成有效的非目標，跟循環播放的決定互相矛盾）。

### 一台公車與三個民眾重複使用，地塊左右兩緣都切

場景裡的物件跟現在一樣多。下一圈的公車就是同一台：一圈結束時它在右緣外，第 0 秒回到左緣外的 `BUS_START_X`（−22），跳過去的那一刻兩個位置都被切掉，看不見。右緣外的位置是 22，對稱於 −22；公車長 12，x ≥ 21 就整台在右緣外。上車的三個民眾在進到車裡時設成看不見，再從右緣外走回來。

切面從一個變成兩個：左緣 x = −15 與右緣 x = 15。`clipToBlock()` 同時套到公車與三個民眾，陰影一起切（`clipShadows`）。司機與站長不會走出地塊，不切。

理由：物件不變，每格要畫的東西跟 `home-page` 量的時候一樣，每格耗時應該差不多（估計，5.1 重新量）；定格畫面裡也正好就是現在這些物件、在現在的位置。公車是通用車，沒有路線號碼，同一台再開進來讀起來就是下一台。人物換成新的造型之後，每個人多一兩個 mesh（眼睛兩顆、頭髮從兩片變一個殼，站長的帽子多一個帽簷），全場多 6 個，照 `person()` 數的；球與膠囊的面也比方塊多，7.4 再量一次。路邊綠化與海報再多 21 個 mesh（三棵樹各 4 個、兩個花台各 4 個、海報 1 個，照設計數的），8.5 再量一次。

替代方案：

- 第二台公車，讓下一台在前一台離開時就進來（否決：一圈裡沒有哪一刻需要兩台車同時在畫面上；公車本身就有 31 個 mesh，照 `bus()` 數的，還要加上它們的陰影）。
- 民眾在站牌前淡入（否決：要透明材質與深度排序；從切面走進來，跟公車的進場方式一致）。

### pose 改吃一圈裡的秒數，匯出用定格畫面的秒數

`scene.js` 的介面：

- `pose(parts, seconds)`：seconds 是從一圈開始算的秒數，任何不小於 0 的值都可以，對 `CYCLE` 取餘數。
- 匯出 `CYCLE`（一圈的秒數）與 `STILL`（定格畫面的秒數，5.5），拿掉 `DURATION`。`buildScene()` 最後擺 `pose(parts, STILL)`。
- `parts` 多兩樣：司機的兩隻手臂（`arm()` 回傳的肩膀群組），以及三個民眾，各帶等車的位置與朝向。
- 前 5.5 秒沿用現在的 `TIMELINE` 數值與緩動，所以 `pose(parts, STILL)` 跟現在的 `pose(parts, 1)` 擺出一樣的姿勢。

匯出頁 `tools/hero/index.html` 的 `?t=`（0 到 1 的比例）改成 `?s=`（一圈裡的第幾秒），匯出一律用 `STILL`；`tools/hero/export.js` 的註解把「最後一格」改成「定格畫面」。

順序：先只改介面、不加新的段落，匯出兩張圖跟 commit 進去的檔逐像素比對，預期 0 個像素不同；之後才加第 5.5 秒以後的段落，每加一段再比一次。

`home-page` 的決定「場景模組放 app/frontend/hero，首頁與匯出頁共用，three 改為 dependency」照舊，只有它寫的「`pose(parts, t)` 依 t（0 到 1）擺姿勢，`t = 1` 就是靜態圖的構圖」改成上面這樣。

理由：循環的時鐘是秒數，取餘數之後 runtime 不用知道一圈裡有哪些段落；定格畫面用一個具名的秒數，匯出與首頁指的是同一格。

替代方案：

- 維持 0 到 1，改成一圈的比例（否決：定格畫面會變成 5.5 / 21 這種比例，時間軸一調，比例就跟著變，匯出會不知不覺換一格）。
- 匯出另寫一個擺定格畫面的函式（否決：兩條路擺同一格，會漂移）。

### 只在看得到、沒暫停的時候重繪

**Supersedes**: home-page / 執行期效能預算：pixel ratio 上限 2、陰影貼圖 2048、只在播放時重繪

照舊的部分：

- pixel ratio 上限 2；陰影貼圖執行期 2048、匯出 4096。
- 兩個預算：首頁動態載入的 chunk brotli 後不超過 200 KB；每格不超過 16 ms。量法也照舊：開發機的 headless Chrome，用 CDP 開 4 倍 CPU 節流，在頁面腳本執行前包住 `requestAnimationFrame`，量每次回呼的執行時間，不計前三次。
- 量到的數字寫回這一節。超出預算時回報，不自己放寬。

改掉的部分：「只在動畫播放期間跑 `requestAnimationFrame`，定格後不再重繪」改成三個條件都成立才畫：

1. 沒有按暫停。
2. `[data-hero-stage]` 至少一半在畫面裡：`IntersectionObserver` 設 `threshold: 0.5`，用 `intersectionRatio >= 0.5` 判斷。不看 `isIntersecting`，它只要有一點重疊就是 true。
3. 瀏覽器在跑 `requestAnimationFrame`：分頁在背景時，瀏覽器本來就不跑。

其他規則：

- 動畫的時鐘（一圈裡的秒數）只在畫的時候前進，每次前進「離上一次回呼的時間」，最多 0.1 秒，所以分頁切回來、插圖捲回畫面時，從停下的地方接著演，不會跳一大段。
- canvas 插進去時先畫第一格，不管看不看得到，canvas 才不會是空白的。
- 停下的時候（暫停或不在畫面裡），尺寸改變照現在播完之後的做法，由 `ResizeObserver` 重畫一格，換鏡頭也是這樣。

### 暫停鈕由伺服器輸出，依 data-hero 顯示，文字跟著狀態換

`HomeHeroComponent` 在 `[data-hero-stage]` 裡、`<picture>` 之後輸出：

```erb
<button type="button" data-hero-pause x-on:click="toggle()"
        class="absolute bottom-3 left-3 z-10 min-h-11 items-center rounded-full border border-slate-200 bg-white px-4 text-table leading-snug font-medium text-slate-700 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-teal-700">
  <span data-label="pause" class="items-center gap-1.5">
    <svg aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><rect x="6" y="5" width="4" height="14" rx="1"></rect><rect x="14" y="5" width="4" height="14" rx="1"></rect></svg>
    <%= t(".pause") %>
  </span>
  <span data-label="resume" class="items-center gap-1.5">
    <svg aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="currentColor"><path d="M8 5v14l11-7z"></path></svg>
    <%= t(".resume") %>
  </span>
</button>
```

- 文案在 `app/components/home_hero_component.yml`：`tw` 與跟著它的 `zh-TW` 是 `pause: 暫停動畫`、`resume: 繼續播放`；`en` 是 `Pause animation`、`Resume animation`。
- 顯示與否寫在 `app/frontend/stylesheets/application.css`，跟其他插圖的規則一樣放在 `@layer` 外面：按鈕與兩段文字預設不顯示；`data-hero` 是 `playing` 或 `paused` 時按鈕顯示成 `inline-flex`；`playing` 時 pause 那段、`paused` 時 resume 那段顯示成 `inline-flex`。按鈕與兩段文字都不放 display 的 class，上面的 `items-center`、`gap-1.5` 在它們顯示成 flex 時才有作用。
- class 的來源：膠囊樣式沿用起點區塊的連結（`min-h-11` 到 `font-medium`，文字色改成 `text-slate-700`），焦點框沿用路線頁的切換鈕。`absolute bottom-3 left-3 z-10` 讓它疊在 canvas 上面（第四次需求變更從右下角移到左下角，見「手機畫面改成 3:2，鏡頭跟著公車移到站牌」）：runtime 把 canvas 加在按鈕後面，沒有 `z-10` 會被蓋住。圖示是 16×16 的內嵌 SVG，暫停是兩條直槓，播放是三角形。
- 行為：`homeHero` 的 `toggle()` 呼叫 `this.animation?.toggle()`。runtime 切換暫停狀態、改寫 `data-hero`，再取消或排下一格。按完焦點留在按鈕上。
- 不記住：Turbo 的快照會還原成 `pending`，按鈕跟著藏起來；下次進來是新的一圈，沒有暫停。

理由：WCAG 2.2.2 要求自動開始、超過 5 秒、旁邊還有其他內容的動態，要讓使用者能暫停、停止或隱藏。減少動態效果的系統設定只照顧到有開的人。按鈕疊在插圖的盒子裡，出現時不會把下面的內容往下推。顯示與否由 CSS 看 `data-hero`，跟靜態圖的藏法一樣是同步的；`turbo:before-cache` 同步把狀態設回 `pending`，快照裡不會留下過期的按鈕。

替代方案：

- 文字固定、用 `aria-pressed` 表示（否決：看得到的人在暫停時看到的還是「暫停動畫」；專案裡用 `aria-pressed` 的按鈕是在幾個選項裡選一個，不是動作）。
- 放在插圖下面（否決：JS 接手後才出現，會把整頁往下推）。
- 由 runtime.js 產生按鈕（否決：文案屬於元件的 yml；伺服器輸出裡沒有它，元件測試與 Turbo 快照都看不到）。

### data-hero 拿掉 done，加上 paused

狀態變成：`pending`（伺服器輸出）→ `loading`（載入動畫的 chunk）→ `playing` ⇄ `paused`；減少動態效果、沒有 WebGL、chunk 載入失敗時是 `static`。不再有 `done`。

### 全景改成約 2.1:1，鏡頭只框地塊與從左緣開進來的車頂

**Supersedes**: home-page / 匯出直接從 canvas 出 WebP，兩個鏡頭、固定尺寸

需求變更（2026-10-23）：使用者看桌機的畫面，覺得插圖上下留白太多。量過：當時 2048×1152 的全景圖，裁掉透明的地方之後，上方空 266 px、下方空 68 px、左右各 48 px（`magick -trim`）。

原因有兩個：

1. 全景鏡頭框的是 x ±15、y −1 到 3.8、z ±6.5 的盒子，盒子左後方上角那一塊是空的。鏡頭畫面上的縱座標約是 `−0.235x + 0.866y − 0.442z`（鏡頭上方向量，方位角 28°、仰角 30°），那個角在 9.7，地塊左後角只到 6.4，中間約 3.3 個單位都是空白。
2. 內容比 16:9 寬：加上 0.8 的邊界，地塊在畫面上寬約 34.2 個單位，16:9 的畫框一定是 19.2 高，比內容高。只收緊盒子的話，空白只會從上面搬到下面。

改成：

- 全景鏡頭框地塊本身（x ±15、y −1 到 0、z ±6.5），再加上公車從左緣開進來時車身頂的後角 (−15, 3.1, −2.8)，它在畫面上的 7.44，是整圈裡最高的地方；車頂空調罩的角在 7.53，落在 0.8 的邊界裡，不會被切掉。`orthographic()` 多一個 `also` 參數，放這種盒子以外要一起框進來的點。
- 全景的匯出尺寸從 2048×1152 改成 2048×976，比例照上面的範圍與邊界算（34.2 比 16.3，約 2.098），頁面上顯示最寬 1024×488 CSS px；`HomeHeroComponent` 的 `img` 寬高跟著改成 1024×488。
- 照舊：匯出頁的兩個按鈕各把 renderer 設成固定尺寸、用對應的鏡頭 render 一次，`canvas.toBlob` 直接存成品質 0.85 的 WebP；直式後來也改了，見「手機畫面改成 3:2，鏡頭跟著公車移到站牌」；預算全景不超過 200 KB、直式不超過 120 KB；超過預算時先降品質到 0.75，再把像素降一級（全景改成 1600×762、直式改成 900×600），預算不放寬。
- 估計的結果（9.1 量）：上方約 111 px、下方約 48 px、左右各約 48 px。量到的（2026-10-23，apply 9.1，`magick -trim`，2048×976）：定格畫面上方 111 px、下方 48 px、左右各 48 px，跟估計一樣；公車正穿過左緣的第 0.6 秒與第 1.0 秒，上方還留 45 px 與 51 px，車頂沒有被切掉。

理由：使用者要上下的空白少一點；兩個原因都要處理，空白才會真的變少。

替代方案：

- 只收緊盒子、維持 16:9（否決：畫框的高度由寬度決定，空白只會從上面搬到下面）。
- 2:1（否決：比內容的比例窄，上下還會各多出約 0.4 個單位的空白）。
- 把地塊的左右兩端裁掉（否決：切開的地塊左右兩端是構圖的一部分，公車與民眾從那裡進出）。
- 再縮小 0.8 的邊界（暫不採用：比例對了之後，剩下的空白主要就是這個邊界，約 48 px；再縮，地塊會貼著畫面的邊）。

## Implementation Contract

行為（看的人看到什麼）：

- 有 JS、允許動態、有 WebGL：插圖的盒子先保留，canvas 淡入，從公車開進來開始演，一圈約 21 秒（設計值），一直循環。人物是圓頭、點點眼睛、膚色。插圖左下角出現「暫停動畫」；按了停在當下那一格，按鈕變成「繼續播放」，再按從同一格接著演。插圖不到一半在畫面裡就不畫，捲回來接著演。播放中或停下時跨過 640 px，鏡頭跟著換。桌機上插圖最寬 1024×488；手機上是 390×260，鏡頭平常停在末站，公車開去站牌時跟過去，下一圈開頭再移回來。路邊有三棵綠色的行道樹與兩個花台；調度室後牆、排班板左邊貼著一張橘底的「洋流」海報。
- 減少動態效果、沒有 WebGL、動畫 chunk 載不到、頁面腳本沒有接手：看到靜態圖（加了人物、綠化與海報之後重新匯出的那兩張），暫停鈕都看不到。
- 首頁 → 別頁 → 上一頁：Turbo 快取裡是伺服器輸出的狀態，回來是新的一圈、沒有暫停，舊的 canvas 與 WebGL context 已釋放。

介面與資料形狀：

- `app/frontend/hero/scene.js` 的 `WIDE` 是 2048×976、`NARROW`（原本的 `TALL`）是 1170×780；`orthographic()` 多一個 `also` 參數；`narrowCamera()`（原本的 `tallCamera()`）停在末站，`aimNarrowCamera(camera, seconds)` 把它移到一圈裡那一刻該看的地方，runtime 每次用窄螢幕的鏡頭 render 之前呼叫它（`render()` 裡，不在 `tick()`），匯出頁 render 之前也呼叫它。
- `app/frontend/hero/scene.js` 匯出 `CYCLE`、`STILL`、`pose(parts, seconds)`；`buildScene()` 回傳的 `parts` 擺在 `STILL`；`WIDE`、`wideCamera()`、`createRenderer()`、`renderFrame()` 不變，`TALL` 與 `tallCamera()` 改名成 `NARROW` 與 `narrowCamera()`；`DURATION` 拿掉。`person()` 照舊回傳 `{ figure, arms }`，造型照「人物改成圓頭、點點眼睛與膚色」；`SKIN` 與 `GREEN_600` 是不在路線頁色票裡的兩個顏色，海報的貼圖用它自己的顏色。
- `scene.js` 的 `buildScene()` 另外把 `greenery()`（樹與花台）與海報加進場景，兩者都不動、不在 `parts` 裡；海報的貼圖由 `poster()` 在建場景時畫好。
- `app/frontend/hero/runtime.js` 的 `start(section)` 回傳 `{ dispose(), toggle() }`；`dispose()` 另外斷開 `IntersectionObserver`。
- `homeHero` 多一個 `toggle()`。
- DOM：`section[data-section=hero]` 的 `data-hero` 是 `pending`、`loading`、`playing`、`paused`、`static` 之一，`data-hero-shot` 是 `wide` 或 `narrow`；`[data-hero-stage]` 裡有 `button[type=button][data-hero-pause]`，底下是 `[data-label=pause]` 與 `[data-label=resume]`。
- 匯出頁：`?shot=wide|narrow`、`?s=<秒數>`（窄螢幕的鏡頭也移到那一刻的位置），匯出用 `STILL`；兩個按鈕是 `[data-shot=wide]` 與 `[data-shot=narrow]`，存成 `home-hero-wide.webp` 與 `home-hero-narrow.webp`。

失敗的情況：

- 動畫的 chunk 載不到：跟現在一樣退回 `static`。
- 支援 WebGL 2 的現行瀏覽器都有 `IntersectionObserver`，不另外處理沒有的情況。
- render 過程丟出錯誤：跟現在一樣不攔，畫面停在最後畫出的那一格。

驗收：

## Risks / Trade-offs

- [手機上一直畫比較耗電、發熱] → 只在看得到、沒暫停時畫；11.2 在手機上開一分鐘看；明顯發熱就另開 change，先考慮限制每秒格數。
- [定格畫面跟靜態圖對不上：多了右緣的切面，民眾也換成被切的材質] → 2.1 到 2.4 每次都匯出比對，不是 0 就修到 0，不重新匯出蓋掉。差異可能有兩種來源：姿勢跑掉，就修姿勢；暫時拿掉新加的切面再匯出一次，差異變回 0，就表示姿勢沒變、差異來自材質多了切面而重新編譯的 shader；這時構圖沒變，就停下來回報使用者，要不要重新匯出由使用者決定，apply 不自己重出。人物換成新造型是使用者決定的（2026-10-23），7.3 因此重新匯出，之後的比對以新檔為準。
- [人物有臉、有膚色，讀起來比較像遊戲或玩具，這是原本「不畫五官」要防的] → 頭身比收在約 1:4、不加腮紅與髮型、色票其餘照舊；11.1 由使用者在 1280 px 與 390 px 的實際大小下看過。
- [人物跟 HEART 政策島的一樣有點點眼睛與膚色，看過兩邊的人可能聯想在一起] → 不加它最有辨識度的大頭、腮紅、髮型與吉祥物；剩下的相似，是使用者看過比較圖、選 C 時接受的代價（2026-10-23）。
- [海報是候選人的競選識別，選前放在首頁，網站會被讀成支持某一邊的；公運處與選後的新市府都是這個網站要說服的對象（`home-origin-story`）] → 使用者看過這個理由與示意圖之後決定放（2026-10-23）；alt 文字照實寫出這張海報，用螢幕閱讀器的人與搜尋引擎讀得到。
- [海報的字用裝置上的字型，macOS、Windows、Android 的字形不同，極少數沒有中文字型的環境會變成方框] → 接受，海報只要看起來像；靜態圖用開發機的 PingFang 匯出。
- [綠色比原本的顏色飽和，會跟站牌的琥珀色搶強調色] → 11.1 看實際大小；太搶就換成 green-700。
- [行道樹在手機直式畫面的左右兩邊被切掉一半] → 11.1 在 390 px 寬看過，再決定要不要挪位置。
- [樹、花台與海報再多 21 個 mesh] → 8.5 重新量每格耗時。
- [實際大小下眼睛只有一兩個像素，C 在頁面上跟 A 差不多] → 接受，使用者是看過比較圖的實際大小那一欄之後選的。
- [人變矮、變寬也變厚，上車與走回站牌的路線是照舊尺寸排的] → 7.2 用匯出頁逐格看，必要時只調 `RIDERS` 的路線與出發時間，`riders()` 的兩個檢查照舊要過。
- [直式鏡頭只框中間，民眾上車那段在框外，手機上只看得到車尾停在畫面右邊] → 使用者看過之後要改（2026-10-23）：鏡頭跟著公車移到站牌，見「手機畫面改成 3:2，鏡頭跟著公車移到站牌」。
- [鏡頭會移動，有人看了會不舒服] → 只在兩段（1.6 秒與 1.2 秒）內緩動平移，其餘時間不動；暫停鈕、減少動態效果、捲出畫面就停照舊；11.1 在 390 px 寬看過。
- [手機畫面移到站牌時，車頂離上緣只剩約 19 px（1170 寬）] → 原型每 0.05 秒掃一整圈，沒有一格碰到上緣；10.1 用改好的程式再掃一次，11.1 在手機寬度看過。
- [手機上動畫的第一格是站牌、還沒有公車，跟靜態圖的末站不同] → canvas 是淡入的，接著鏡頭移到開進來的公車；11.1 在 390 px 寬看過。
- [手機上看不到調度室與牆上的海報] → 接受：鏡頭只在末站與站牌之間移動，調度室在末站左邊、框外。
- [圖檔改名，`home-hero-tall.webp` 的網址不再有效] → 網址本來就帶 digest，每次重新匯出都會變；頁面上只有 `HomeHeroComponent` 引用它，其餘是匯出頁的檔名、`scene.js` 的註解與插圖的 spec（`git grep`，2026-10-24），10.1 到 10.3 一起改。
- [全景變矮，頁面上的插圖從 1024×576 變成 1024×488，下面的起點區塊往上移約 88 px] → 這就是使用者要的；直式不變。
- [系統測試要等超過一圈，CI 多二十幾秒（估計：一圈 21 秒加 2 秒的餘裕，6.2 的 `bin/ci` 看實際時間）] → 只有一個例子等一整圈，其他例子在第一圈裡判斷。實測（2026-10-23，6.2）：`bin/ci` 的平行 RSpec 共 53 秒，跑到 `spec/system/home_hero_spec.rb` 的那個 worker 44 秒，其他 worker 約 26 秒，整套 `bin/ci` 1 分 16 秒。
- [一圈的秒數寫死在系統測試裡，時間軸調了測試沒跟著改] → spec 的常數旁註明對應 `scene.js` 的 `CYCLE`；動到時間軸的任務要一起改它。
- [視窗矮到插圖永遠不到一半在畫面裡，動畫不會開始，canvas 停在第 0 秒那一格] → 只有非常矮的視窗會碰到，那一格是還沒有車的末站，接受。
- [民眾上車時穿過站牌桿或彼此] → 上車的路線繞過站牌桿、依序走；2.3 用匯出頁的 `?s=` 逐秒看，換人物之後由 7.2 再看一次。
