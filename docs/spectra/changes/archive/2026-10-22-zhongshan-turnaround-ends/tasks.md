## 1. 設定與折返點的性質

- [x] 1.1 實作 Verified end nature per route 與 Missing or unknown end nature is an error，套用 design「折返點的性質是逐路線查證後寫進設定的事實，不從資料推」「路線清單改成以路線 Id 為鍵的對應表，兩端的性質缺一就擋下」「測試路線 9001 兩端都標停車，開過去就走的行為用明確傳入的性質測」：`config/route_page.yml` 從 `route_ids` 列表改成 `routes` 對應表，`shared` 的 15373 兩端是 `0: pass_through`、`1: stop`，值旁的註解記查證日期 2026-10-22 與證據（青年公園(馬場町) 到青年社宅約 200 公尺、2026-10-20 的 75 筆折返停留中位數 1.9 分鐘、GPS 沒有離開這一段），`test` 的 9001 兩端都 `stop`；新增 `RoutePage::Ends`（`app/models/route_page/ends.rb`）與 `RoutePage.ends(route_id)`，`RoutePage.route_ids` 改成回對應表的鍵（整數陣列）；`RoutePage::Ends.from_config(hash, route_id:)` 缺 0 或 1 任一方向、或值不是 `stop` 與 `pass_through` 之一時丟 `RoutePage::Ends::InvalidConfiguration`，訊息含路線 Id 與方向，值不對時含那個值；提供 `#nature`、`#stopping?`、`#stopping_go_backs`、`#pass_through_go_backs`、`#pass_through?`。驗證：新增 `spec/models/route_page/ends_spec.rb` 斷言 Scenario「Both ends of 中山幹線」（`RoutePage.ends(15373)` 方向 0 是 `pass_through`、方向 1 是 `stop`）、「Route list is the set of configured routes」（test 環境的 `RoutePage.route_ids` 是 15373 與 9001）、「One direction missing」（訊息含 9001 與方向 1）、「Unknown value」（訊息含 9001、方向 1 與 `depot`）；`spec/requests/routes_spec.rb` 既有的「路線不在路線清單裡回 404」仍綠。

## 2. 試算

- [x] 2.1 實作 Measured base of the estimate、Rest achievement、Added vehicle-hours as a range、Added vehicles in the busiest hour 的修改，以及 Layovers at a pass-through end are not rest opportunities 在試算裡的那一半，套用 design「試算只算停車端的折返停留，開過去就走那一端只報筆數」與「查詢物件與元件不讀設定，由控制器解出兩端的性質再傳進去」：`RoutePage::BufferTrade.new(route_days, minutes:, ends:)`，`HOURS_SQL` 只取 `go_back` 在 `ends.stopping_go_backs` 裡的折返停留，`#n_layovers` 是停車端的筆數，新增 `#n_pass_through_layovers` 數結束在開過去就走那一端的筆數；`#achieved_share`、`#vehicle_hours`、`#peak` 只用停車端；停車端 0 筆時 `#n_layovers` 是 0，走既有的沒有折返停留分支，不除以零。驗證：`spec/models/route_page/buffer_trade_spec.rb` 既有例子加上兩端都 `stop` 的 `ends` 後數字不變（Scenario「Coverage reported」2 天、4 次停車端、0 次開過去就走、8 趟、2.5 台；Example「Four layovers over two days」下限 0.2、上限 0.5；「Hour 8 is busiest」8 點 0.1 與 0.4；「Tie goes to the earlier hour」7 點 0.2），新增斷言 Scenario「Pass-through end reported, not counted」（基礎 1 次、開過去就走 3 次）、「Pass-through layovers do not count」（50.0%）、「Layovers only at a pass-through end」（達成率、車時、車數都是 nil，開過去就走 3 次）、Example「Pass-through layovers add nothing」（0.2 與 0.5）、「Pass-through hour ignored」（下限 8 點 0.3、上限 8 點 0.5，沒有 17 點）。 [after: 1.1]

## 3. 路線頁

- [x] 3.1 實作 Page content 的折返停留表部分、Layover distribution chart 的修改，以及 Layovers at a pass-through end are not rest opportunities 在頁面上的那一半，套用 design「頁面上每一端標出性質：文案用「停車」與「開過去就走」，程式用 stop 與 pass_through」與「查詢物件與元件不讀設定，由控制器解出兩端的性質再傳進去」：`RoutesController#show` 在 404 判定之後算 `@ends = RoutePage.ends(route_id)`；`app/views/routes/show.html.erb` 把 `@ends` 傳給 `RoutePage::BufferTrade.new(route_days, minutes:, ends:)`、`LayoverTableComponent.new(layover_stats:, ends:)`、`LayoverChartComponent.new(layover_distribution:, ends:)`；折返停留表每列 `tr[data-direction]` 加 `data-end-nature`（`stop` 或 `pass_through`）與一欄「停車」或「開過去就走」，路線有開過去就走的一端時表下多一句說明（車到末站不停、直接開到下一趟的起站，這一端的折返停留不是休息機會）；分佈圖每個方向的 `figcaption` 加 `data-end-nature`，標題句尾接上「停車」或「開過去就走」；文案放兩個元件同層的 `.yml`（tw、zh-TW、en）；表與圖的數字不變，不加顏色、不標合不合規。驗證：`spec/components/layover_table_component_spec.rb` 斷言 Scenario「End nature on the layover rows」（方向 0 `pass_through`、方向 1 `stop` 時兩列的 `data-end-nature` 與那一欄的文字，筆數與百分位數跟既有例子相同）；`spec/components/layover_chart_component_spec.rb` 斷言 Scenario「Title states the end nature」（兩個 `figcaption` 的 `data-end-nature`），既有的「標題寫出末站與下一趟出發的起站」仍綠；`spec/requests/routes_spec.rb` 斷言 Scenario「Both ends stopping」的表格部分（9001 兩列 `data-end-nature="stop"`），既有的區塊順序（Scenario「Overlap block in place」）、400 與 404 的例子不變；`spec/requests/route_page_fixture_spec.rb` 仍沒有任何車牌、Bullet 不報 N+1；`spec/models/route_page/card_consistency_spec.rb` 不改仍綠。 [after: 2.1]
- [x] 3.2 實作 Page content 的試算部分，套用 design「頁面上每一端標出性質：文案用「停車」與「開過去就走」，程式用 stop 與 pass_through」：`BufferTradeComponent` 的涵蓋率那句報停車端的筆數（`data-value="layovers"`）；`@buffer_trade` 來自有開過去就走一端的路線時（`ends.pass_through?`），多一句報那一端的筆數（`[data-value=pass-through-layovers]`）並寫明不是休息機會、不算，沒有這種一端時這個元素不出現；沒有停車端的折返停留時說明文字寫「沒有量到停車端的折返停留」；元件簽章 `BufferTradeComponent.new(buffer_trade:, coverage:)` 不變，`RoutePage::BufferTrade` 要讓元件拿得到 `ends`；文案放 `app/components/buffer_trade_component.yml`（tw、zh-TW、en）。驗證：`spec/components/buffer_trade_component_spec.rb` 斷言 Scenario「Pass-through layovers in the estimate block」（方向 0 `pass_through` 結束 3 筆、方向 1 `stop` 結束 2 筆時 `layovers` 是 2、`pass-through-layovers` 是 3），兩端都 `stop` 時沒有 `pass-through-layovers` 元素、既有的 `layovers` 2 與其他欄位數字不變；`spec/requests/routes_spec.rb` 斷言 Scenario「Both ends stopping」的試算部分（9001 的頁面沒有 `pass-through-layovers`）。 [after: 3.1]
- [x] 3.3 實作 Data limitations on the page 的修改：`app/components/data_limitations_component.yml` 的 tw 與 en 把試算那條改成只用停車端量到的折返停留，並新增一條：哪一端停車是逐路線查證後寫進設定的、不是從資料算的、業者改折返方式時會過期，開過去就走那一端的折返停留不是休息機會、試算不補它。`docs/spectra/LANGUAGE.md`：「起站、末站、折返點、調度站」那條把工作樹裡還沒 commit 的青年公園端那句併進來，定義加上折返點的屬性「停車或開過去就走」，「在資料或程式碼裡」寫 `config/route_page.yml` 的 `ends` 與 `RoutePage::Ends`、值是 `stop` 與 `pass_through`，「邊界」寫青年公園端照定義仍是折返點只是車不停、調度站或路邊的區分留待之後，「不要用」補上「不停站」（那講的是中途過站不停，不是這件事）；「換休息試算」那條的「邊界」改成只算停車端、開過去就走那一端只報筆數，「在資料或程式碼裡」補 `#n_pass_through_layovers`。驗證：固定文案照專案的 TDD 規則不寫斷言，做內容審查對照 `route-page` 與 `turnaround-ends` 的 delta spec 與 design 的「頁面上每一端標出性質」那條；`spec/requests/routes_spec.rb` 區塊順序那個例子裡 `limitations` 仍在。 [after: 3.2]

## 4. 真資料
