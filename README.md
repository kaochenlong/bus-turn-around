# TurnAround 折返點

這個網站量的，是每台公車到了末站、再開出去之前，實際停了多久，以及沿線載了多少人。

網站：<https://bus.5xcamp.us>

## 要解決的問題

台北公車缺司機，缺額依來源與時點在 12% 到近三成之間，路線又跟捷運疊床架屋。2023 到 2026 年市府對 288 條路線中的 147 條做了調整、80 條調降離峰服務水準，但調整的依據是「哪裡人不夠就減哪裡」，不是「哪裡最該減」。

市府的審議規則早就有兩個門檻：與捷運重疊 70% 以上可列為裁撤或縮短對象、尖峰每班次低於 5 人上下車可檢討。缺的是證據，沒有人持續、公開、逐路線地量「重疊路段實際載多少人」和「折返點實際能休幾分鐘」。有了這兩個數字，路線調整才有機會從「省錢」改寫成「把省下來的駕駛工時換成合法的休息與穩定的班距」，政治上比較推得動，也才處理得到駕駛過勞的問題。

完整的背景、附日期的數字、法規錨點與來源在 [docs/background.md](docs/background.md)。

## 交付物

網站上每條路線一頁（路線頁），可以看一天，或最近 7 天裡跟那一天同一種日型別（平日或假日）的日子。目前有路線頁的是中山幹線、251、251區 與 307，307西藏三民 併在 307 一起算。頁面依序是：

1. 摘要與站序：起訖、涵蓋的日子、趟次數，以及站序與路線軌跡地圖。
2. 折返停留：每一端是停車還是直接折返，停留的分佈（p10、p50、p90）與不到 15 分鐘的比例。
3. 來回與週期：同一台車跑一個來回要多久，以及兩次回到停車端之間隔多久。
4. 折返點設施：每一端 300 公尺、500 公尺內有幾處公廁，附地圖。
5. 換休息試算：假設停車那一端的每次折返都多留一段緩衝（0 到 20 分鐘，預設 15），算每天要多花幾車時、最忙的那個小時要多派幾台車（都給上下限），以及目前停留不少於緩衝的比例。算的是車的時數，不是駕駛的工時。
6. 行駛時間：每個方向依發車小時的 p50、p85、p95。
7. 載客剖面與捷運重疊：沿線的車上人數、靠近捷運的站與路段、分時段的逐站數字。
8. 資料限制。

頁面只報數字，不標示有沒有超過門檻，也不給建議。

路線頁的換休息試算卡與名稱列連到「班表」頁：用量到的行駛時間百分位數（p50 到 p95 可選）、停車端每次休息幾分鐘、每個方向每小時幾班，鋪出一條路線一天、一車一張、欄位照行車憑單的班表；在頁面上改發車時間、刪列、加列，數字立刻重算，印出來帶走。當天要用的是名稱列連過去的「當天調度」頁：用量到的資料鋪出今天的計畫（平日或假日照星期幾預設、可以換，百分位數與休息可以選），按「開始當天」之後記下哪台車幾點回來、把一班改派給另一台車、改發車時刻，看每一班誰開、停了幾分、哪一班車還沒回來；這一天存在調度員那台電腦的瀏覽器裡，要留著就「印出當天紀錄」（摘要一頁、一車一頁），或匯出修改清單與最後的單兩個 CSV。鋪排、重算、當天調度與它的列印、匯出都在瀏覽器裡，伺服器只給量到的資料，什麼都不存；班表頁與當天調度頁要有 JavaScript，是網站僅有的例外。

另外，`bin/health-card` 直接讀原始檔，產出一條路線一天的健檢卡（Markdown）。一天版只用來驗證指標的定義，不能引用，範例在 [docs/cards/](docs/cards/)。

## 誰受益

1. 公車駕駛：折返點實際停多久，第一次有人在量，而且可以拿去對照法規。想要班表加緩衝、終點站有廁所，手上也有數字可以講，不只是抱怨。
2. 公運處：面對民代和業者的時候，有逐路線、公開可以驗證的依據，不再只能被動減班。
3. 業者：可以排出合法又跑得完的班表，脫班罰款和留不住人的成本都有機會降下來。
4. 乘客：班距比較穩、脫班比較少、司機不用趕。

工具本身不會讓任何人多休息一分鐘，要等有人做了決定才會有好處。如果資料被拿去單純減班，那就是用錯地方了。

## 明確不做

- 乘客用的到站 app 或即時地圖。
- 全網排班最佳化。那是排班研究的題目，本系統提供它需要的輸入。一條路線一天、一車一張的班表不算最佳化：它照固定規則鋪一次，給調度員改。
- 依賴拿不到的票證 OD 或 TDX 歷史資料。

## 架構

```
data.taipei 公車即時 feed
  └─▶ n-gear：每 10 秒採集、去重、每小時 JSONL，兩小時後壓成 .jsonl.gz（唯一的資料來源，衍生結果隨時能重算）
        └─▶ DuckDB：算趟次、折返停留、載客剖面、捷運重疊、折返點設施、路線軌跡
              ├─▶ bin/health-card：一天版健檢卡
              └─▶ PostgreSQL：只放算好的衍生表，由 bin/rails derived:load 寫入
                    └─▶ Rails：路線頁、首頁
```

採集器 n-gear 是另一個 repo。衍生表由 Mac mini 每晚算好，直接寫進正式站（`bin/nightly-load`），`bin/push-derived` 只在正式站清空時用。網頁只查衍生表，不碰原始檔。為什麼這樣切，見 [docs/decisions.md](docs/decisions.md)。

## 資料來源與授權

原始資料是臺北市公共運輸處依「政府資料開放授權條款第 1 版」釋出的開放資料。各資料集、其他外部資料、顯名聲明的原文見 [docs/data-sources.md](docs/data-sources.md)。提供資料不代表該機關推薦、同意或核准本專案。

## 開發

技術棧與慣例見 [AGENTS.md](AGENTS.md)。

```sh
bin/setup   # gem、前端套件、git hooks、開發與測試資料庫
bin/dev     # Rails server 與 Vite
bin/ci      # RuboCop、bundler-audit、Brakeman、平行 RSpec、seeds
```

衍生表與健檢卡要用 n-gear 收的原始檔來算，資料根目錄用環境變數 `TURNAROUND_DATA` 指定，`bin/rails derived:load`、`bin/nightly-load` 與 `bin/health-card` 的用法見 [analysis/README.md](analysis/README.md)。

需求與計畫用 Spectra 管理：規格在 `docs/spectra/specs/`，進行中的 change 在 `docs/spectra/changes/`，專案脈絡在 `docs/spectra/config.yaml`。

## 名字

折返點是公車掉頭的地方，也是司機在兩趟之間休息的地方，取這個名字也是希望這套制度能在這裡轉彎。英文 turnaround 同時有車輛折返和局面翻轉的意思。採集器叫「空檔 Neutral」，gem 名 n-gear，N 檔就是空檔。班表裡的空檔是司機能休息的時間，車子打空檔引擎才真的歇著。
